## 0. 结论先行

1. 真正的亮点不多，而且集中。94 个运行里，同题其他运行都没有做到的处理共 14 处（第 3.1 节），其中 10 处出自 Anthropic 模型，7 处出自同一个条件 Opus 5.5 · HyperFrames；Astra · HyperFrames 3 处，V4.1-Flash · HyperFrames 1 处，Sol 和 V4-Pro 没有。最强的 7 处见下表和第 5 节拼图。
2. 亮点分两类，对应两种可以拉开差距的能力：
   - 言外之意：画面说出题面或歌词没写的东西。例如 cc-hf-B2 用倒影补上缺席的人，cc-hf-C1 用墙上的画预告结尾，codex-hf-B2 用空座位上的红伞替代离开的人。
   - 把机制算出来、而不是画出来：cc-bare-S1 和 cc5-bare-S1 的天空颜色由散射计算得出，并与太阳高度、路径倍数联动；cc5-bare-I1 让颜料沿笔触真的流动，而不是原地抖动。
3. 新跑完的 cc-hf-B2、cc-hf-C1 改变了前一份报告的排序。前一份报告认为 C1 叙事最好的是 dsh-hf-C1、B2 最像 MV 的是 codex-hf-B2；加入这两部后，C1 和 B2 的叙事与意象都是 cc-hf 最好。
4. 现有 rubric 草案几乎奖励不到这些亮点。L1 和 L2 是找缺陷的，L3 只有 C4“非默认感”笼统相关。第 4 节给出 12 个加分题和 5 个可计算指标，并建议按“同题稀有度”决定哪些亮点计分：同题多数运行都做到的（例如 B1 画面踩拍 7/9）只算及格。

## 1. 方法与口径

| 项目 | 做法 | 局限 |
|---|---|---|
| 数据 | 面板的 HTTP 服务一次只接少量连接，下载约 130 KB/s。我改为经 `ssh cpu001` 让服务器上的 ffmpeg 把每部成片转成 960 px 宽、保留原音轨的 MP4，直接输出到标准输出，本机接收到 `/tmp/c2v-hl-narr/v/`。没有在服务器上写文件。拼图用的帧经同样方式取原分辨率 | 960 px 足够看构图和动作，看小字时不够 |
| 时序观察 | 每部片先做 1 fps 联系表（`/tmp/c2v-hl-narr/sheets/`），候选处再做 2–10 fps 的放大拼图。第一轮四题先做“每行一个运行”的总览图（`/tmp/c2v-hl-narr/rows/`） | 1 fps 会漏掉短动作，所有写进表的时刻都在放大拼图上复核过 |
| 声音 | 每 0.1 s 的 RMS；用频谱通量找起音；把起音与画面事件时刻对齐（`/tmp/c2v-hl-scripts/av.py`，结果 `av.jsonl`） | 小物体的碰撞在全局帧差上不明显，所以以起音为候选、回到画面核对 |
| 画面是否踩拍 | 节拍周期从音频细扫得到 0.438 s；30 fps 帧差按周期折叠，与错误周期的零分布比较，报告 z 值（`beatlock.py`） | 只测“运动是否有节拍周期”，不区分运动是内容事件还是全屏脉动 |
| I1 运动质量 | 地面 / 天空运动比、块匹配输运率、首尾接缝比（`i1.py`、`i1flow.py`） | 输运率会把缩放也算成流动，需与地面 / 天空比一起看 |
| 对照 | 每个亮点都写了同题其他运行在同一位置做了什么 | 每格只有一次运行，“稳定习惯”的判断靠跨题重复出现，不是同题重跑 |

标注规则：没有写“推断”的，都是直接在帧上看到或量出来的。秒数都是成片时间。“亮点”的门槛是：超过题目及格线，并且同题多数运行没有做到。

## 4. 对 rubric 加分项的建议

### 4.1 结构

现有三层（L1 确定性检查、L2 二元 checklist、L3 成对比较）都以找缺陷为主。建议在 L2 增加一类“加分题”（记为 B 类），规则如下：

1. B 类题只在 Q 类全部通过后才作答，避免“有亮点但没完成题目”的片子得分。cc-hf-M1 就是例子：一般性演示是亮点，但画面上有字母，按严格的“不用一个字”Q 类不过，B 类不作答。
2. 每题要求 judge 先描述、再给出时间点、最后判“是 / 否”。没有时间点的“是”按“否”处理。
3. 按同题稀有度定权重：一轮评测结束后，某道 B 类题的通过率超过 50%，就把它降为该题的及格线，不再加分（第 3.4 节就是这个过程）。这与草案 §5 的“难度分层，事后标定”一致。
4. L3 增加一个维度 C6“言外之意”：“哪个视频的画面说出了题面或歌词没直接写、但让你记住的东西？”。现有 C4“非默认感”问的是风格是否专门，C6 问的是内容是否超越字面，两者在本组数据上会给出不同结论（例如 dsh-hf-B2 的夜景配色在 C4 上好，但没有言外之意）。
